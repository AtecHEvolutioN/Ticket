# Ticketmaster coverage check — 10 November 2026

Probed **92 distinct events across 14 country sites**, representing **90 artist or
show labels** in the [public target manifest](../examples/coverage-2026-11-10.json).
The browser captured 89 pages successfully. Replaying the updated parser over
those captures extracted **242 displayed price/type rows from 75 events**; every
row had a normalized price and currency. These are displayed categories, not
confirmed stock or quantities that can be fulfilled. This run observed no
interpreted resale offer rows.

The other results were 11 sale-schedule views, one presale-code view, one page
reporting no tickets in its current view, one German map-display adapter gap,
and three transport failures. The page-state descriptions were reviewed manually;
the parser still reports unknown inventory for these pages. A schedule, gate,
empty view, or transport failure does not establish an event-wide sellout.

each public event URL, the original transport result, capture time/hash, normalized
observation, and any separate follow-up diagnosis. Artist and venue labels come
from the manifest and are not independent identity proofs.

Fixes from this audit and the retained capture corpus:

- Added display-only parsing for reviewed US quick-pick cards, preserving ticket
  type, visible price, section and row. Different price quotes remain distinct;
  card counts and search quantities are not interpreted as ticket stock. Locked,
  hidden, disabled or inconsistent cards are omitted.
- Added display-only parsing for the reviewed Italian selection layout, including
  visible ranges and fee text. The amount shown does not establish a final total
  including fees. Both new adapters require matching event URL evidence and
  compatible currency evidence; metadata prices never become live inventory.
  Italian language-alternate URLs are accepted only under the reviewed binding
  rules when no canonical URL exists.
- Added the observed German best-available display and cookie-rejection labels.
  The regression fixture verifies that these display actions do not select or
  reserve tickets. A fresh Rod Stewart follow-up stopped at HTTP 401, so live
  extraction after this fix remains unverified.
- Added a specific queue-boundary diagnostic for the reviewed waiting-room
  redirect, stopping before following it. Preserved a confirmed same-event
  HTTP 401 response when navigation subsequently fails, instead of losing it
  behind a generic navigation error.
- Rejected blank, control-character, query-only and fragment-only metadata
  identity links before URL resolution. They can no longer inherit the watched
  event and supply unrelated currency or availability metadata.

The three original transport failures remain in the totals: Hilary Duff in Italy
reached a queue boundary; a separate Luke Combs diagnosis observed HTTP 401;
Gracie Abrams navigation failed without a confirmed HTTP status. These diagnoses
do not demonstrate reliable unattended access to those events.

A **separate offline replay of the 9 November capture corpus** increased events
with interpreted display details from 12 to 14 and displayed rows from 49 to 96.
Its two previously interpreted resale offers remained unchanged. That comparison
validates the new US/Italian parsers against saved pages; it is not fresh US/Italian
access and is not added to the 242-row total above.

To repeat the read-only audit from the repository, build the release binary and
install the browser dependencies as described in the README. Run headed mode on
a graphical desktop; use `CHROMIUM_PATH` if selecting an installed Chromium:

```bash
node browser/coverage.cjs --input examples/coverage-2026-11-10.json \
  --output captures/artist-audit/report.json \
  --capture-dir captures/artist-audit/pages \
  --binary target/release/ticket-watch --headed --limit 92 \
  --timeout-ms 45000 --host-gap-ms 2000 --max-minutes 45
```

The runner uses the production direct-navigation display adapter and recognized
display controls only. It does not select seats, change quantities, press Find
tickets, reserve tickets, enter checkout, or send Discord messages. Protection
responses and Retry-After stop that host for the run. `--resume` retains known
host blocks and reuses saved captures.

Replay requires the private captures produced by your own run and makes no
provider requests:

```bash
node browser/coverage.cjs --input examples/coverage-2026-11-10.json \
  --output captures/artist-audit/replay.json \
  --capture-dir captures/artist-audit/pages \
  --binary target/release/ticket-watch --limit 92 --replay
```

Replayed observations retain `observed_at: 0`; capture times and hashes are
recorded separately. Raw HTML stays in the ignored private capture directory.
The published report contains no credentials, raw session captures or live cart
journal data.

Validation passed: **450 Rust tests**, **162 browser-suite tests with zero skips**,
formatting, Clippy and the release build. The Android APK is unchanged. This
one-shot audit does not measure ticket-release-to-alert latency or verify
remaining stock, fulfillment, adjacent seats, or continuous monitoring access.
